# 知乎回答朗读需求稿 v0.1

- 状态：草稿，待确认
- 日期：2026-10-29
- 变更：初稿，根据现有产品描述整理；未引入已批准版本。

## 1. 背景与目标

面向使用 Chrome 和 Microsoft Edge 浏览知乎网页版的用户，提供以**单条回答**为单位的朗读体验。用户在回答的赞同和反对操作附近找到喇叭入口，点击后扩展尝试展开该回答并朗读可读取的正文，让用户可以边听边查看当前段落。

参考页面：[知乎回答示例](https://www.zhihu.com/question/8742907044/answer/2096610574620800318)。该链接用于说明场景，不代表页面结构固定，也不保证任何回答都能完整提取。

第一版接受使用浏览器自带语音，即使用户此前认为其音质不佳。产品希望以 MIT 许可证开源；项目代码的许可不改变知乎页面内容的权利状态。

## 2. 第一版范围

### 2.1 入口与回答选择

- 在知乎网页版每条可识别回答的赞同、反对操作附近提供喇叭朗读入口。入口与对应回答的关联应清楚，避免误读其他回答。
- 点击入口后，针对该回答尝试自动展开正文，再尽量读取页面上可获得的完整正文。只读取用户当前页面可访问的内容，不要求绕过登录、付费或其他访问限制。
- 页面动态加载或更新回答时，扩展应能为新增的可识别回答提供入口，并避免同一回答出现重复入口。页面结构变化或回答无法识别时，不能假定入口或提取始终成功。

### 2.2 朗读与控制

- 第一版通过浏览器提供的语音能力朗读提取到的文本，支持暂停、继续和停止。可用声音及音质可能受浏览器、操作系统和声音提供方影响，不承诺特定声音或音质。
- 按回答正文段落呈现当前朗读位置：朗读到某段时高亮该段；朗读结束或停止后清除高亮。无法对应到页面段落的内容不应造成错误的段落高亮。
- 朗读期间切换到其他浏览器标签页，原回答的朗读继续；关闭回答页时停止该页的朗读。
- 同一页面中点击另一条回答的朗读入口时，停止当前回答并切换到新选择的回答，避免两条回答同时朗读。切换前同样尝试展开和提取新回答；如果新回答无法朗读，应给出提示。

### 2.3 提取失败与不完整提示

- 找不到可朗读正文、展开失败或语音播放出错时，向用户提供可理解的提示，不静默表现为成功。
- 能识别出正文可能仍被折叠、截断或提取不完整时，提示用户朗读内容可能不完整；是否继续朗读已取得内容可由具体交互设计决定，但不能把部分内容表述为确定完整。
- 无法保证检测到所有截断或遗漏。图片、视频、公式等非普通文本内容，以及页面结构、登录、付费或其他访问限制，可能影响朗读内容；产品说明应让用户了解这一限制。
- 读取页面已显示文字不需要复制到剪贴板。页面可能显示禁止转载等提示；扩展应以页面阅读辅助为目标，不因读取或使用开源许可证而声称拥有回答内容的使用权。

### 2.4 语音服务扩展点

- 将朗读控制与具体语音服务解耦，为将来替换或增加服务保留接口。接口需要能表达开始朗读、暂停、继续、停止，以及段落进度、完成和错误等状态，使页面交互不必依赖某一家服务。
- 第一版仅要求接入浏览器语音能力，不要求接入第三方服务、提供第三方配置界面或实现通用的零适配接入。将来的新服务可能需要专门的适配器。

## 3. 第一版验收场景

以下场景用于验证目标行为；涉及真实知乎页面和实际语音能力的结果，还需在目标浏览器和可访问页面上验证。

| 场景 | 预期结果 |
| --- | --- |
| 在可识别的回答中点击喇叭 | 扩展尝试展开该回答，读取可获得的正文并开始朗读；入口与回答对应。 |
| 朗读中暂停、继续、停止 | 暂停后不再继续朗读，继续后恢复；停止后结束朗读并清除高亮。 |
| 朗读跨越段落 | 当前可对应的正文段落高亮随朗读进度切换；结束后清除高亮。 |
| 切换浏览器标签页，随后关闭回答页 | 切换标签后原页继续朗读；关闭回答页后该页朗读停止。 |
| 同页选择另一条回答 | 当前回答停止，扩展尝试展开并朗读新回答；不能朗读时提示用户。 |
| 页面动态加载新回答或更新已有回答 | 可识别的新回答获得入口，同一回答不重复添加入口。 |
| 正文找不到、展开失败或检测到可能不完整 | 给出对应提示；若朗读已取得的部分，用户能知道可能不完整。 |
| 浏览器语音不可用或播放失败 | 给出可理解的错误提示，避免界面持续显示正在朗读。 |

## 4. 后续方向（不属于第一版承诺）

- 按配置接入第三方语音服务，并视服务能力实现适配器；具体服务、配置方式、凭据管理、错误处理和费用由后续需求确定。
- 在接入外部服务前明确会传输什么回答内容、传给谁、何时传输，以及告知、授权和数据处理方式。浏览器自身可提供不同来源的声音，实际数据处理也可能受所选声音提供方影响，不能笼统承诺所有声音均离线。
- 根据真实页面兼容性和用户反馈，改进正文提取、截断识别、朗读体验和支持范围。

## 5. 待确认事项

1. **多标签页播放关系**：目前只要求同一页面切换回答，以及切换标签时继续朗读；不同标签页是否允许同时朗读，还是全浏览器只保留一个播放，待确认。
2. **切换失败时的体验**：新回答无法提取或播放时，是否需要恢复上一条回答，或保持停止并提示，待确认。
3. **不完整内容的交互**：检测到可能不完整时，是自动朗读已取得内容并提示，还是先让用户选择，待确认。
4. **页面导航与刷新**：关闭回答页必须停止；同标签页内导航、刷新或页面内容被替换时的具体停止与恢复行为，待确认。
5. **朗读设置**：第一版是否需要声音、语速等可配置项，以及其默认值和保存范围，待确认；这不影响第一版使用浏览器语音的基本要求。
6. **界面细节和适配范围**：按钮样式、提示文案、键盘及辅助技术体验，以及需要重点验证的知乎页面类型和浏览器版本，待结合设计与测试确认。
7. **开源发布**：MIT 许可的版权声明及发布准备由权利人确认；回答内容权利与项目代码许可分别处理。
